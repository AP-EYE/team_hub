# 평가 설계 (2026-09-19)

## 1. 벤치마크 실측

직접 문서를 세어 확인한 결과다.

### OWASP crAPI

로컬 클론 `D:\SJH_Data\SecurityLab\crAPI\docs\challenges.md` 기준. 명시된 챌린지 18개에 비공개 3개가 더 있다.

| 분류 | 챌린지 | 우리 범위 |
|---|---|---|
| BOLA | 1번 타 사용자 차량 정보, 2번 타 사용자 정비 리포트 | 대상 |
| BFLA | 7번 타 사용자 영상 삭제 | 대상 |
| Excessive Data Exposure | 4번 타 사용자 민감정보 노출, 5번 영상 내부 속성 노출 | 대상 |
| Unauthenticated Access | 14번 인증 검사 없는 엔드포인트 | 인접 |
| 범위 밖 | 3번 인증, 6번 레이트리밋, 8·9·10번 Mass Assignment, 11번 SSRF, 12번 NoSQL, 13번 SQLi, 15번 JWT, 16·17·18번 LLM | 제외 |

**인가 취약점 3개, 과잉 노출 2개.**

우리가 이미 재현한 것은 1번이다. `GET /identity/api/v2/vehicle/{vehicleId}/location`

### VAmPI

README 기준 취약점 9종.

- SQLi Injection
- **Unauthorized Password Change**
- **Broken Object Level Authorization**
- Mass Assignment
- **Excessive Data Exposure through debug endpoint**
- User and Password Enumeration
- RegexDOS
- Lack of Resources & Rate Limiting
- JWT authentication bypass via weak signing key

BOLA는 책의 비밀 필드다. README 원문:

> Each book is unique for every user and only the owner of the book should be allowed to view the secret.

과잉 노출은 `GET /users/v1/_debug`로 "Displays all details for all users"다.

**인가 취약점 1개, 인가 인접 1개(비밀번호 무단 변경), 과잉 노출 1개.**

### 합계

**인가 관련 챌린지 총 5개.** 이 중 현재 연구의 주평가 대상인 읽기 BOLA는 crAPI 2개와 VAmPI 1개로 **3개**다. 쓰기·비밀번호 변경 2개는 별도 후속 범위다. 따라서 이 세 건만으로 일반적인 탐지 재현율을 주장하지 않는다.

## 2. 소표본 문제와 대응

읽기 BOLA 세 건만으로 recall을 재면 한 건 차이가 약 33퍼센트포인트가 된다. 숫자가 크게 흔들리므로 **공개 챌린지 탐지율만으로 연구 결론을 내리지 않는다.**

### 대응 1 - 조건을 비교한다

비교 대상은 사람의 입력량과 함께 **확인 판정의 정확성·자동 확정 범위**다. 보류를 많이 하면 오탐이 낮아 보이므로 두 축을 분리하지 않는다.

| 도구 | 사람이 넣어야 하는 것 |
|---|---|
| ZAP Access Control Testing | 사용자별로 페이지마다 Allowed, Denied, Unknown |
| Autorize | 저권한 세션 헤더, 판정용 응답 매칭 필터 |
| 이 프로젝트 | 최소 두 계정과 소수 테스트 객체의 공개·비공개·공유 근거. 공유 시나리오는 세 번째 계정 사용 |

실험 설계는 이렇다.

- **조건 A**: ZAP에 Access Rules를 전부 채워 주고 돌린다. 이것이 상한선이다
- **조건 B**: ZAP에 Access Rules 없이 돌린다
- **조건 C**: 우리 도구에 계정과 소수 테스트 객체의 접근 근거만 주고 돌린다. 객체별 입력량과 소요 시간을 기록한다

가설은 C가 전체 권한표를 작성하는 A보다 적은 수동 입력으로 **일부 검사 사례에서** 확정 판정을 낼 수 있다는 것이다. A와 C에는 같은 계정·객체·요청 집합을 제공하고, C에 제공한 테스트 객체 근거는 A의 입력 비용과 함께 집계한다. AuthProbe 등 선행 도구와 비교할 때 명세·목록 API와 추가 요청 수의 차이를 별도 표기한다.

사람이 실제로 쓴 시간을 함께 잰다. 테스트 객체를 만들고 공유 설정을 확인하는 데 든 시간까지 C의 비용이다.

### 대응 2 - 오탐을 따로 잰다

VAmPI에 안전 버전 스위치가 있다. README 원문:

> One nice feature to running it this way is you can startup a 2nd container with `vulnerable=1` on a different port and flip easily between the two.

`vulnerable=0`으로 띄운 컨테이너는 알려진 취약 시나리오의 대조군이다. 해당 시나리오에서 위반으로 확정한 건을 오탐으로 센다. 다른 경보 전체를 자동으로 오탐으로 간주하지 않는다.

**오탐 측정은 보통 정답을 만들기 어려운데 VAmPI가 구조적으로 제공한다.** 이 실험은 반드시 넣는다. 탐지율만 높고 오탐이 쏟아지는 도구는 현장에서 안 쓴다.

### 대응 3 - 홀드아웃을 직접 만든다

crAPI와 VAmPI는 취약점 위치가 문서에 공개돼 있다. 보면서 튜닝하면 과적합이 난다.

**튜닝용과 채점용을 분리한다.** 자체 API에서는 테스트 객체와 미표시 객체를 객체 ID 단위로 분리하고, 다른 엔드포인트 검사는 별도로 채점한다. 진단기는 미표시 객체의 정답 라벨을 받지 않는다.

- 튜닝: crAPI
- 채점: VAmPI + 자체 구축 취약 API

자체 API는 같은 경로와 필드 형태에서 공개·비공개·특정 계정 공유가 달라지는 객체를 만든다. 정상·취약 버전, 공유 해제 전후, 같은 객체를 읽는 다른 엔드포인트를 둔다. 상담 예약·상담 내역·시술 이력의 비정형 필드는 개인정보 분류 실험에 활용한다. 자세한 판정 범위는 [2607.16754 쉬운 정리와 우리 가설](../docs/research/2607.16754%20%EC%89%AC%EC%9A%B4%20%EC%A0%95%EB%A6%AC%EC%99%80%20%EC%9A%B0%EB%A6%AC%20%EA%B0%80%EC%84%A4.md) 7절을 따른다.

## 3. 필드 분류 평가는 사정이 다르다

여기는 표본이 충분하다. 엔드포인트 하나에 응답 필드가 수십 개이므로 **필드 단위로 세면 수백 개**가 나온다.

### 베이스라인은 Presidio

같은 응답 본문을 두 곳에 넣고 비교한다.

| | 판정 대상 |
|---|---|
| Presidio + 한국 recognizer | 값이 어떤 엔티티인가 |
| 이 프로젝트 | 이 필드가 개인정보보호법상 어떤 등급인가 |

측정 항목은 셋이다.

1. **Presidio가 잡은 것을 우리도 잡는가** (회귀 방지). 주민등록번호 같은 정형 값에서 우리가 더 못하면 안 된다
2. **Presidio가 놓친 것을 우리가 잡는가** (기여). 상담 동기처럼 엔티티가 없는 필드
3. **법적 등급이 맞는가**. 민감정보, 고유식별정보, 일반 3분류 정확도

3번의 정답은 [법적 근거](../docs/plan/%EB%B2%95%EC%A0%81%20%EA%B7%BC%EA%B1%B0.md)의 조문으로 정한다. 사람이 임의로 라벨링하지 않는다.

### 정답 라벨의 근거

- 민감정보: 법 제23조제1항 본문(건강, 성생활, 사상·신념, 정치적 견해, 노동조합·정당) + 시행령 제18조(유전정보, 범죄경력, 생체인식, 인종·민족)
- 고유식별정보: 시행령 제19조 네 개(주민등록번호, 여권번호, 운전면허번호, 외국인등록번호)
- 일반 개인정보: 그 외

**애매한 필드는 별도 등급으로 빼고 정확도 계산에서 제외한다.** 화해에서 유출된 "피부 고민 및 타입"이 건강정보인지가 그 예다. 억지로 판정하면 정답 자체가 신뢰를 잃는다.

## 4. 최종 지표

| 실험 | 지표 | 표본 |
|---|---|---|
| 읽기 인가 판정 | 전체 위반 재현율, 확정 판정 정밀도, 자동 확정 범위, 보류율, 사람 입력 시간, 추가 요청 수 | crAPI·VAmPI 읽기 BOLA 3건 + 자체 API의 객체별 사례 |
| 공개·공유 오탐 | 공개·공유 객체를 위반으로 잘못 확정한 비율. VAmPI 정상 버전의 해당 시나리오도 확인 | 자체 API 공개·공유 사례 + VAmPI 해당 사례 |
| 필드 분류 회귀 | Presidio 대비 정형 PII 누락률 | 필드 수백 개 |
| 필드 분류 기여 | Presidio 미탐지 필드 중 우리가 잡은 비율 | 필드 수백 개 |
| 법적 등급 | 3분류 정확도 | 필드 수백 개 |
| 비용 | 엔드포인트당 LLM 호출 수, 토큰 | 전체 |

인가 판정은 보류를 포함한 범위·정확도·수동 입력 비용을 함께 보고한다. 개인정보 분류 성과는 위반 확인 뒤의 별도 실험으로 해석한다.
