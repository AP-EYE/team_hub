## 직접 연결되는 추가 근거

### Rennhard 등, 2022

확인 수준: high. [학술지 원문](https://link.springer.com/article/10.1007/s42979-022-01271-1)의 Misago 평가와 Discussion을 확인했습니다.

> “if the crawler does not find legitimately reachable content or links to such content are missing, there may be false positives”

크롤러가 합법적으로 접근 가능한 내용을 발견하지 못하거나 해당 링크가 없으면 오탐이 발생할 수 있다는 뜻입니다.

Misago 평가에서는 모든 사용자가 다른 사용자의 프로필에 접근할 수 있지만, 게시글을 작성하지 않은 사용자에게는 프로필 링크가 발견되지 않을 수 있었습니다. 연구진은 각 사용자가 공개 글을 하나 이상 작성하도록 테스트 데이터를 준비했습니다. 따라서 ‘탐색 누락으로 생기는 오탐’을 새로운 문제 발견으로 주장하지 않습니다. 탐색을 보완하는 방법도 비교군에 포함해야 합니다.

### FlowWatcher, CCS 2015

확인 수준: high. [저자 공개 원문](https://lsds.doc.ic.ac.uk/sites/default/files/ccsfp224-muthukumaran_0.pdf)의 §3 및 §4를 확인했습니다. 웹 도구의 PDF 스크린샷은 오류로 반환되어 이번 검토는 추출 본문을 기준으로 했습니다.

> “UDA policies do not have to be complete but can capture a subset of the application’s access control model.”

정책 전체를 작성할 필요 없이 앱의 인가 모델 일부를 표현할 수 있다는 뜻입니다.

개발자가 의도한 정책을 규칙으로 작성하고, 생성·공유·그룹 변경에 대응하는 HTTP 요청을 통해 별도의 권한 상태를 갱신합니다. 이를 반환 데이터와 대조해 비인가 노출을 차단합니다. 의도한 정책과 실제 반환을 분리하거나 작은 정책 입력을 사용하는 것 자체는 새롭지 않습니다. 앱별 URL·필드에 맞춘 규칙 작성과 유지 비용을 비교할 필요가 있습니다. 운영 중 차단하는 프록시이므로 동일한 GET 스캐너로 간주하지 않습니다.

### AuthzTrace, 공개 구현

확인 수준: high. 2026-10-02에 [README](https://github.com/Asttr0/AuthzTrace#readme)와 [공식 corpus 문서](https://github.com/Asttr0/AuthzTrace/blob/main/docs/CORPUS.md)를 확인했습니다. 논문이 아닌 공개 도구이며, 설명된 기능과 실제 대상 앱에서 측정한 성능을 구분합니다.

> “Every executable `allow` row must pass before deny rows run.”

금지 접근 검사 전에 실행 대상인 허용 접근 검사가 모두 통과해야 한다는 뜻입니다.

계정, 객체 ID, 객체 표식, 허용 규칙을 계약 파일에 넣습니다. 소유자·특정 계정·로그인 사용자·전체 공개 규칙을 지원하며, 응답 표식으로 실제 내용을 검사합니다. 알려진 허용 요청을 먼저 검사하고 인증·객체 준비 실패를 구분합니다. 따라서 ‘테스트 객체+작은 권한 입력+객체 표식’ 조합만으로 기여를 주장할 수 없습니다. 동일 사례에 대한 수동 계약 입력 방식은 핵심 비교군입니다. 실제 실행과 준비 시간 비교는 아직 하지 않았습니다.

### ZAP와 BOLABuster의 위치

[ZAP 공식 문서](https://www.zaproxy.org/docs/desktop/addons/access-control-testing/)는 사용자별 Allowed·Denied·Unknown 규칙과 부모 URL 규칙의 상속을 설명합니다. 모든 객체의 권한을 하나씩 적는 방식만을 기존 비교군으로 두지 않습니다. Unknown이라는 입력 상태와 우리 판정 보류 결과도 동일한 기능으로 단정하지 않습니다.

[BOLABuster 공식 소개](https://unit42.paloaltonetworks.com/automated-bola-detection-and-ai/)는 AI 기반 테스트 생성·응답 분석과 사람의 확인을 설명합니다. 브리핑의 보조 참고로만 사용하며, 공개·공유 오탐을 처리하지 못한다고 단정하거나 공개되지 않은 오탐률을 만들어 비교하지 않습니다.

## 수정할 주장

기존 표현: 조회 결과와 별도로 기록한 객체 설정을 권한 근거로 사용하는 점이 차별성 후보입니다.

수정 후보: 테스트 객체의 설정 근거를 확보하고 진단 직전에 재확인하는 절차가, 관찰 기반 판정 및 수동 부분 정책 입력과 비교해 어느 준비 비용에서 어떤 판정 개선을 제공하는지 검증합니다.

독립적인 정책 근거, 테스트 객체, 표식, 보류 자체를 새 기법으로 주장하지 않습니다. 기존 정책 입력 방식을 사실상 다시 구현한 결과라면 연구 기여가 부족합니다. 성능 개선과 비용 이점이 없을 가능성도 실험 결과에 포함합니다.

## 평가에 추가할 조건

1. 같은 계정·객체 ID·조회 요청을 고정합니다. 객체 발견 범위가 늘어난 효과와 권한 근거를 추가한 효과를 분리합니다.
2. AuthzTrace식 수동 계약 입력과 탐색·테스트 데이터 보완을 비교합니다. ZAP의 부분 정책·상속도 고려합니다. 원도구 실행과 절차 재구현을 구분합니다.
3. 자연스럽게 발생한 목록 누락과 목록에서 항목을 인위적으로 제거한 조건을 구분합니다. 인위적 제거 실험은 판정 규칙의 민감도이며 원도구 전체 성능으로 해석하지 않습니다.
4. 앱 정책과 설정 상태를 별도로 검토해 평가 정답을 확정합니다. 판정기 입력값을 복사해 정답으로 삼지 않습니다. 실제 위반은 금지된 보호 내용이 반환되는지 확인하고 거부 대조군과 대조합니다.
5. 공개된 객체 ID·제목만 노출된 경우와 비공개 본문 노출을 구분합니다. 객체 ID 일치만으로 보호 내용 누출을 확정하지 않습니다.
6. 설정 직후와 진단 직전 상태가 달라졌거나 하위 객체 권한 상속을 확인하지 못한 경우에는 보류합니다. 권한 회수 후 세션 진단으로 연구 범위를 확장하지 않습니다.
7. 준비 비용에는 앱 정책 해석, 필드 연결, 설정 확인, 객체 초기화·재확인과 사람의 검토 시간을 포함합니다. 동일 사례 비용과 같은 준비 시간 안에서 평가 가능한 사례 수를 함께 제시합니다.
8. 재현율은 전체 실제 위반을 분모로 하고, 보류·미검사 위반도 미탐으로 셉니다. 오탐률은 전체 정상 사례를 분모로 합니다. 보류율을 별도 제시하며 확정 사례만의 수치는 보조 지표로 표시합니다.

## 반영하지 않은 주장과 남은 확인

- AuthProbe가 공유를 무조건 오탐한다는 표현, EvoMaster의 LLM이 BOLA 오탐을 줄였다는 표현은 가져오지 않습니다. [2026-10-02 문서 허브 논문 대조](2026-10-02%20%EB%AC%B8%EC%84%9C%20%ED%97%88%EB%B8%8C%20%EB%85%BC%EB%AC%B8%20%EB%8C%80%EC%A1%B0.md)의 원문 대조 결과를 유지합니다.
- Taxonomy의 action 41.7%, direct object reference 36.9%를 읽기 취약점의 빈도라고 바꾸지 않습니다. 읽기 범위는 일정·재현 가능성을 기준으로 한 실험 선택입니다.
- TrafficAuthzRisk의 합성 데이터 성능은 우리 앱에서의 BOLA 판정 성능 근거로 사용하지 않습니다.
- 팀 조사에 제시된 ‘Policy-aware interface contracts for testing access-control and selected privacy obligations in service APIs’(DOI 10.1016/j.cola.2026.101424)는 이번에 원문 내용을 확보하지 못했습니다. 중복 가능성은 추가 확인 사항이며, 이를 이유로 선행연구가 없다고 주장하지 않습니다.
- 위 비교와 비용 측정은 계획이며 실제 도구 실행 결과가 아닙니다. [2026-10-02 노션 브리핑 발표 대본](../../discussion/2026-10-02%20%EB%85%B8%EC%85%98%20%EB%B8%8C%EB%A6%AC%ED%95%91%20%EB%B0%9C%ED%91%9C%20%EB%8C%80%EB%B3%B8.md)도 변경된 주장에 맞춥니다.
