# 권한 단서 조사 재검증 (2026-09-29)

## 재집계

원본 [2026-09-29 권한 단서 실태 조사](2026-09-29%20%EA%B6%8C%ED%95%9C%20%EB%8B%A8%EC%84%9C%20%EC%8B%A4%ED%83%9C%20%EC%A1%B0%EC%82%AC.md)에는 `secret`, `access`, `audience`, `permissions`를 뺐다는 설명이 있지만 `authz_signal_survey.py`에는 이 이름을 포함하는 넓은 정규식만 있다. 따라서 원본의 엄격 기준 10.0%를 제공된 스크립트만으로 재현할 수 없다.

저장된 `authz_signal_survey.json`에 `authz_signal_audit.py`의 명시적 엄격 정규식을 적용했다. GET이 하나 이상인 명세 가운데 전체는 **133/2,034 = 6.5%**, 대형 클라우드 제외는 **95/1,003 = 9.5%**였다. 이 값도 필드 이름이 한 번이라도 맞은 **후보 명세 비율**이다. GET 엔드포인트, 객체, 실제 응답, 서비스 비율이 아니다. 제외 집합의 명세 1,003개는 `:` 앞 API ID로 묶으면 제공자 616개이며, 후보 95개에는 GitHub 계열 명세가 20개 포함된다. 제공자 단위 후보는 72/616이지만 한 제공자 아래 여러 제품이 있을 수 있어 별도 서비스 비율로 해석하지 않는다.

## 30개 명세 문맥 검토

후보 95개에서 제공자 ID별 첫 명세를 고른 뒤 고정 시드 `20260929`로 30개를 추출했다. 각 명세의 GET 2xx 응답 스키마에서 일치 필드의 경로·타입·설명을 확인했다. `적합`은 필드가 조회된 객체 또는 응답에 명시적으로 포함된 객체의 공개·공유 상태를 가리킨다는 뜻일 뿐, **해당 호출의 인가 위반을 확정한다는 뜻이 아니다.** `보류`는 이름과 위치만으로 의미를 확정하기 어렵다는 뜻이다.

## 가설에 미치는 영향

`private=true` 또는 `visibility=private`는 **불특정 사용자에게 공개되지 않음**을 뜻할 수 있지만, 테스트 계정 B가 공유 대상·조직 구성원·협업자인지까지 말하지 않는다. 따라서 이 필드만으로 B의 접근 금지 근거를 세우면 SNS·협업 API에서 오탐할 수 있다. 확인 가능한 금지 근거는 통제된 B 계정이 공유되지 않았다는 실험 설정, B가 없음을 뜻하는 완전한 ACL, 또는 서비스가 명시한 권한 규칙과 함께 확보해야 한다. 필드의 대상 객체·엔드포인트도 실제 재생 요청과 일치해야 한다. 다른 엔드포인트에서 얻은 필드는 탐색 후보에만 쓴다. 이는 [2607.16754 쉬운 정리와 우리 가설](2607.16754%20%EC%89%AC%EC%9A%B4%20%EC%A0%95%EB%A6%AC%EC%99%80%20%EC%9A%B0%EB%A6%AC%20%EA%B0%80%EC%84%A4.md)의 보류 원칙과 맞춘다.

발표에서는 **"공개 명세 1,003개 중 95개(9.5%)에서 이름 기준 후보를 찾았고, 제공자 중복을 줄인 30개 문맥 검토에서 17개가 객체 공개·공유 상태에 해당했다. 인가 위반 판정 가능률은 아직 측정하지 않았다"**고 말할 수 있다. "문제가 생기는 10%", "남은 90%는 보류", "필드만으로 미표시 객체를 확정"은 현재 자료로 뒷받침되지 않는다.

다음 실험은 `후보 필드 발견 → 실제 객체 상태 확인 → 테스트 계정 B의 비공유 근거 확인 → 같은 객체 재생 응답 확인 → 판정/보류`를 각각 분모와 함께 기록해야 한다. 보류 8개는 제공자 문서나 실제 테스트 API의 정의로 재판정하고, 후보가 아닌 명세도 무작위 표본으로 확인해 이름 규칙의 누락을 추정한다. 선행연구 신규성은 이 실태 조사만으로 확정하지 않는다. [OpenAPI 권한 기술의 한계를 논의한 논문](https://arxiv.org/abs/2212.06606)은 표준 보안 기술의 한계를 지적하지만, 권한 의도를 반드시 응답 필드에서만 얻어야 한다고 증명하지 않는다.
