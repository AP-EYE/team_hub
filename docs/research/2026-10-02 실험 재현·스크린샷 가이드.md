3. 아래를 한 줄씩 붙여 넣는다.


## 1. 실험 1: Gitea, 단순 규칙의 오탐 (15분)

무엇을 보여주나: 인가가 정상인 앱에서도 "타인이 200을 받으면 위반"이라는 단순 규칙이 공개 조회와 공유 조회를 위반으로 잡는다.

### 1-1. Gitea 띄우기

```powershell
docker rm -f gitea-bola 2>$null
docker run -d --name gitea-bola -p 3300:3000 -e GITEA__security__INSTALL_LOCK=true -e GITEA__database__DB_TYPE=sqlite3 -e GITEA__server__ROOT_URL=http://localhost:3300/ gitea/gitea:28.0.0
Start-Sleep -Seconds 15
docker exec -u git gitea-bola gitea admin user create --admin --username rootadm --password "Rootpass123!" --email rootadm@test.local --must-change-password=false
```

확인할 것: 마지막에 `New user 'rootadm' has been successfully created!`가 나온다.

### 1-2. 실험 스크립트 실행

```powershell
python gitea_bola_probe.py | Tee-Object -FilePath gitea_bola_probe_result.txt
```

이 스크립트가 하는 일:
1. 계정 3개를 만든다. alice(주인), bob(권한 없음), carol(공유받음). 비밀번호는 모두 `Testpass123!`이다.
2. alice가 저장소 3개를 만든다. pub(공개), priv(비공개), shared(비공개 + carol에게 읽기 공유). 저장소마다 이슈 1개를 만든다.
3. bob(B), carol(C), 비로그인(anon)이 저장소 3개와 이슈 3개를 조회한다. 총 18건이다.
4. 단순 규칙 판정(naive)과 정답(truth)을 나란히 출력한다.

확인할 것: 마지막 줄이 `naive false positives: 8/18`이다.

**S1 촬영**: 표 18줄과 마지막 줄이 한 화면에 나오게 찍는다.

표 읽는 법 (브리핑 설명용):
- `status`: 200은 조회 성공, 404는 Gitea가 권한 없는 사람에게 비공개 저장소를 없는 것처럼 보여준 것이다.
- `naive`: 단순 규칙 판정. 남의 것을 200으로 받으면 "위반"이다.
- `truth`: 정답. 객체를 만들 때 정한 공개 상태로 판단한다.
- `naive_correct`가 False인 8줄이 오탐이다. pub 조회 6건, carol의 shared 조회 2건이다.
- 이 앱은 인가가 정상이라 실제 위반(truth=위반)은 0건이다.
- 저장소 응답에는 `private` 값이 있지만 이슈 응답은 None이다. 이슈는 부모 저장소의 공개 상태를 따른다.

### 1-3. 브라우저로 같은 상황 보여주기

1. 일반 창에서 http://localhost:3300/user/login 에 `alice` / `Testpass123!`로 로그인한다.
2. http://localhost:3300/alice 로 간다. priv와 shared에 비공개 표시가 붙어 있다.
   - **S2 촬영**: 저장소 3개가 보이게 찍는다.
3. 시크릿 창(`Ctrl + Shift + N`)에서 `bob` / `Testpass123!`로 로그인한다.
4. http://localhost:3300/alice/priv 를 연다. 404 화면이 나온다.
   - **S3 촬영**: 주소창과 404 화면이 같이 보이게 찍는다.
5. 시크릿 창에서 로그아웃하고 `carol` / `Testpass123!`로 로그인한다.
6. http://localhost:3300/alice/shared 를 연다. 정상으로 열린다.
   - **S4 촬영**: 주소창과 저장소 화면이 같이 보이게 찍는다.

사전 확인 결과(2026-10-02): alice는 세 저장소 모두 200, bob은 pub만 200, carol은 pub과 shared가 200이었다.

## 2. 실험 2: Memos 0.9.0, 공개 범위 3단계 (10분)

무엇을 보여주나: 메모마다 공개 범위(PUBLIC, PROTECTED, PRIVATE)가 다른 앱에서도 같은 오탐이 난다. 이 버전은 BACScan(CCS 2025)이 정답 세트로 쓴 앱이라 나중에 재현율 측정에 쓴다.

### 2-1. Memos 띄우기

```powershell
docker rm -f memos-090 2>$null
docker run -d --name memos-090 -p 5230:5230 neosmemo/memos:0.9.0
Start-Sleep -Seconds 10
```

### 2-2. 실험 스크립트 실행

```powershell
python memos090_visibility_probe.py | Tee-Object -FilePath memos090_visibility_probe_result.txt
```

이 스크립트가 하는 일:
1. 첫 계정 alice(관리자)를 만들고, alice가 bobby를 만든다. 비밀번호는 `alicepass`, `bobbypass`다.
2. alice가 PUBLIC, PROTECTED, PRIVATE 메모를 하나씩 만든다.
3. bobby와 비로그인(anon)이 메모 3개를 조회한다. 총 6건이다.

확인할 것:
- 위쪽에 `signup alice 200`, `signin bob 200`이 나온다.
- 마지막 줄이 `naive false positives: 3/6`이다.

**S5 촬영**: 아래 표와 마지막 줄이 보이게 찍는다.

표 읽는 법:
- PUBLIC은 누구나, PROTECTED는 로그인한 사용자만, PRIVATE는 주인만 볼 수 있다.
- bobby의 PUBLIC·PROTECTED 조회와 비로그인의 PUBLIC 조회는 정상인데, 단순 규칙은 위반으로 본다. 그래서 3건이다.

주의: 이 스크립트는 빈 컨테이너에서만 alice 가입이 성공한다. 다시 돌릴 때는 2-1부터 다시 한다.

### 2-3. 브라우저 화면 (선택)

1. http://localhost:5230 에 `alice` / `alicepass`로 로그인한다.
2. 메모 3개가 보이면 **S6 촬영**.

이 화면은 사전 확인을 하지 못했다. 로그인이 안 되거나 공개 범위가 화면에 안 보이면 S6은 건너뛰고 S5로 대신한다.

## 3. 실험 3: crAPI를 쓰지 않는 이유 (5분)

무엇을 보여주나: 처음 계획한 crAPI는 객체마다 공개 상태를 정할 수 없다. 그래서 Gitea와 Memos로 바꿨다.

```powershell
git -C D:\SJH_Data\SecurityLab\crAPI grep -n -i -E "visibility|is_public|is_private|shared_with" -- services | Measure-Object -Line
python -c "import json;s=json.load(open(r'D:\SJH_Data\SecurityLab\crAPI\openapi-spec\crapi-openapi-spec.json',encoding='utf-8'));print('endpoints:',sum(1 for p in s['paths'].values() for m in p if m in('get','post','put','delete','patch')))"
```

확인할 것:
- 첫 번째 명령의 `Lines`가 0이다. crAPI 소스에 객체별 공개 설정 필드가 없다는 뜻이다.
- 두 번째 명령이 `endpoints: 44`를 출력한다.

**S7 촬영**: 두 결과가 한 화면에 나오게 찍는다.

설명용 한 줄: crAPI는 공개 여부가 엔드포인트 종류로 고정돼 있다(게시글은 공개, 차량 위치·주문은 주인만). 같은 엔드포인트 안에 공개 객체와 비공개 객체를 섞어 만들 수 없다.

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `docker`를 찾을 수 없다 | PATH에 Docker 없음 | 0단계 첫 줄(`$env:Path += ...`)을 다시 실행 |
| `error during connect ... dockerDesktopLinuxEngine` | Docker Desktop이 꺼짐 | Docker Desktop을 켜고 20초 기다린 뒤 다시 실행 |
| `port is already allocated` | 3300이나 5230을 다른 컨테이너가 사용 | `docker ps`로 확인하고 그 컨테이너를 `docker stop` |
| `python`을 찾을 수 없다 | PATH에 Python 없음 | 0단계의 `$py` 줄을 넣고 `& $py 스크립트이름.py`로 실행 |
| Memos `signup alice`가 200이 아니다 | 이미 계정이 있는 컨테이너 | 2-1부터 다시 실행 |
| Gitea 스크립트가 `AssertionError` | Gitea가 아직 뜨는 중 | 30초 기다렸다가 1-2만 다시 실행 |
| 한글이 깨진다 | 출력 인코딩 | 0단계의 `$env:PYTHONIOENCODING = "utf-8"` 다시 실행 |
