## EvoMaster 학술지 원문 확인

허브에 첨부된 PDF를 `papers/EvoMaster-JSS_113060_2026.pdf`로 저장했다.
24쪽의 추출 텍스트는 `data/EvoMaster-JSS_113060_2026.txt`다.
[학술지 원문](https://doi.org/10.1016/j.jss.2026.113060)은 Journal of Systems and Software 243, 113060, 2027년 권호의 온라인 공개본이다.

| 위치 | 직접 확인한 내용 | 브리핑 반영 |
|---|---|---|
| §3.3, PDF 6~7쪽 | 같은 계정·객체에서 PUT·PATCH·DELETE의 거부·성공 불일치를 검사 | GET 읽기 비교군과 구분 |
| §3.3, PDF 7쪽 | 정상 정책에서도 동사별 권한이 달라 오탐이 가능. 수동 평가 후 해당 엔드포인트의 오라클 비활성화 가능 | 근거 부족 판정과 수동 검토 비용의 문제 연결 |
| §5 | 일반 퍼징 결과로 추가 보안 테스트를 생성하는 사후 처리 | 사후 처리를 사람의 정책 검토와 같은 의미로 쓰지 않음 |
| §7, PDF 22쪽 | LLM으로 발견된 결함의 종류를 분류하는 후속 가능성 | BOLA 오탐 감소의 구현·실측 성과로 쓰지 않음 |

팀 요약의 “A는 거부되고 B는 성공하는 패턴”은 §3.3의 핵심 조건을 충분히 표현하지 않는다.
원문의 해당 비교는 같은 계정·같은 객체에서 수정 동사를 바꾸는 절차다.
다른 계정의 읽기 성공만으로 위반을 확정하는 도구의 대표로 쓰지 않는다.

## AuthProbe 원문 확인

[원문 HTML](https://arxiv.org/html/2607.20574)의 §V-F·§VII·§VIII를 확인했다.
평가는 합성 채용 API의 취약·강화 버전 두 개를 사용한다.
기본 탐지 실험은 두 계정이 각각 객체 3개를 가진 조건이다.
공개·로그인 공개·선택 공유가 섞인 실제 앱의 성능으로 일반화하지 않는다.

목록이 없을 때 명시적 객체 입력을 사용하는 가능성도 이미 원문에 있다.
그러므로 객체 ID를 직접 입력한다는 점만으로 차별성을 주장할 수 없다.
제안 방법의 추가 근거는 객체 ID와 별개인 공개 범위·계정별 공유 관계다.

## 연구를 구체화한 내용

- 입력: 객체 ID, 생성자, 공개 범위, 공유 계정·권한, 설정 시각·성공 근거.
- 반환 확인: 객체 ID와 합성 표식으로 대상 객체 일치 확인.
- 비교: 같은 공유 객체가 B 목록에 있는 조건과 빠진 조건에서 AuthProbe식 판정과 설정 근거 판정을 대조.
- 범위: EvoMaster §3.3은 쓰기 동사 검사이므로 GET 읽기 재현율의 비교 분모에 포함하지 않음.
- 한계: 설정 입력 자체의 새로움과 비용 절감은 아직 입증되지 않음.
