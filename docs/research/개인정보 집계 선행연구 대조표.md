### 지금 가설에 가장 직접적인 한계

> “Future work will characterise degradation under partial noise via systematic label-corruption experiments”
>
> → 후속 연구에서는 체계적인 라벨 오류 주입 실험으로 부분적인 잡음 아래에서 성능이 어떻게 저하되는지 규명한다.
>
> P06, §5.1 A. Sensitivity label reliability. 출판사 검색 색인에서 직접 확인한 구절이다.

이는 **입력 민감도 오류를 후속 조치 순위와 연결해야 한다는 근거**다. 동시에 그 문제의식이 우리만의 발견이 아님을 뜻한다. AP-EYE는 실제 한국어 분류 오류를 얻고, 같은 검토 예산으로 결과를 개선하는 방법까지 대조해야 한다. 그래프 구조가 다른 P06의 수치와 우리 점수를 직접 비교해서는 안 된다.

### P04는 얼마나 강한 근거인가

P04는 ‘PII+취약점 점수’ 조합의 선행성 근거다. 실증의 강도는 별개다.

- PII는 사전 정의한 스키마와 분류체계에서 정하며, AI는 문맥 계수를 보조한다. 한국어 자유서술 분류기가 아니다.
- `PIIComposite = min(7, Smax + 0.25 × (Npii−1))`을 사용한다. 이미 최대 민감도와 PII 필드 수를 결합했다.
- §3.8 예시의 `5.25×3×3×1.6`은 75.6인데 72로 적혀 있다. 113.4로 정규화하면 66.7점이며, 인쇄된 63.5점과 다르다. [개인정보 분류 오류의 순위 영향](%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%20%EB%B6%84%EB%A5%98%20%EC%98%A4%EB%A5%98%EC%9D%98%20%EC%88%9C%EC%9C%84%20%EC%98%81%ED%96%A5.md)의 감사 스크립트로 산술을 확인했다.
- [저자 코드](https://github.com/umashankarak/pii-aware-pentest-demo)의 `index.js`는 입력된 네 계수를 곱하고 정규화한다. PII 탐지와 AI 추론 전체를 재현하는 구현은 아니다. 실행하지 않고 소스를 읽었다.

따라서 **선행연구로 인용하되 강한 검증 기준으로 혼동하지 않는다.** 공식을 기준선으로 재구현할 때 출판 예시 숫자를 그대로 복사하지 않는다.

K07을 한국어로 미세조정했다는 개인 모델 카드들도 검색됐다. 학습·평가 분할과 라벨 정책이 서로 달라 숫자만 나란히 놓지 않는다. 현재 단계에서는 후보 목록을 늘리기보다 **같은 AP-EYE 시험셋에서 규칙, 한국어 인코더, 현재 로컬 모델의 세 기준선**부터 비교하는 편이 낫다.

## 5. 코드와 원문의 실제 확보 상태

- P01이 연결한 [http-pii-annotator](https://github.com/tomcory/http-pii-annotator)는 **확인 시점에 빈 저장소**였다. ‘저자 코드로 재현 가능’이라고 적으면 안 된다. 논문을 보고 구현하면 ‘방법 재구현’이다.
- P04의 공개 코드는 곱셈·정규화 데모다. 논문 전체 시스템과 구분한다.
- P07은 Edu-Sens에 실제 필드명과 합성 값을 사용했다고 밝힌다. 코드·Edu-KG는 저자 요청 방식이며 즉시 공개 다운로드와 다르다. 이번에는 연락하지 않았다.
- P06은 합성 데이터 공개를 주장하지만 이번 접근 범위에서 실제 파일·라이선스까지 검증하지 못했다. 원문 전체와 자산 확인이 남았다.
- P05의 arXiv는 PoPETs 2026을 journal reference로 표시한다. 이번 노트는 로컬에 보관한 arXiv v1을 읽은 결과이며 별도 출판본의 동일성을 검증한 것은 아니다.

## 7. 검색 범위와 남은 공백

검색일은 2026-09-30이다. 기존 Vault 자료를 먼저 읽고 2026년 7~9월 자료를 추가 탐색했으며, 이미 선점된 방법을 확인하기 위해 2010~2025년 기반 연구도 포함했다. 웹 검색, arXiv, ACL Anthology, 출판사, 공식 GitHub·모델 카드, 국가법령정보센터를 사용했다.

`research-hypothesis/scripts/search_papers.py`로 다음 다섯 쿼리와 두 시드의 인용 그래프를 실행했다.

```text
privacy risk score sensitivity analysis
personal data classification uncertainty ranking
privacy breach severity aggregation
decision focused learning predict optimize
active learning ranking value information
--cite arXiv:2605.06305 --cite arXiv:2512.04120
```

결과는 `data/privacy_aggregation_search_2026-09-30.json`이다. 별도 주제 탐색 결과는 `data/search_scorer_assumptions.json`에 있다. 전자는 Cory 인용 0건, Telkamp 인용 1건을 반환했다. **색인에서 0건이라는 뜻이며 실제 인용·선행연구가 없다는 뜻은 아니다.** 관련성이 낮은 결과는 근거 목록에서 제외했다.

웹에서는 `PII-aware penetration testing risk scoring`, `sensitivity labels privacy leakage ranking`, `subject-level PII`, `Korean PII detection`, `privacy risk uncertainty`, `selective classification`, `conformal risk control`, `hybrid personal data detection`, 해당 논문 표제·DOI를 추가 검색했다.

이는 가설 선택을 위한 범위 조사다. 모든 학술 데이터베이스를 빠짐없이 수집한 체계적 문헌고찰은 아니다. 특히 P06·P08·K03·K05·G05의 전체 원문·자산 검토가 남아 있어 ‘최초’나 ‘선행 부재’를 결론으로 쓰지 않는다.
