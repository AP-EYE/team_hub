## 2. 정답 자료의 단위

응답 한 개마다 다음 항목을 남긴다. 실제 운영 로그와 연구 정답 파일은 별개다.

| 그룹 | 필드 예시 | 목적 |
|---|---|---|
| 출처·분할 | `service_id`, `schema_family`, `endpoint_id`, `template_id`, `split` | 같은 템플릿·서비스 누출 방지 |
| 요청·관측 | 메서드, 정규화 경로, JSON 경로, `capture_id`, 관측 시점, `present/nonempty` | 스키마 존재와 실제 반환 구분 |
| 인가 근거 | `authz_status`, `evidence_id`, 테스트 주체·객체 식별자 | Scorer가 인가 판정을 만들지 않게 함 |
| 정답 의미 | 값의 개체 구간, 일반/고유식별/민감 다중 라벨, 비개인정보, 판단 불충분 | NER·의미·법적 매핑 오류 분리 |
| 정보주체 | `subject_ref`, 관계 종류, `subject_link_status` | 환자·가족·구매자·수령인 등 구별 |
| 집계 | `fact_ref`, 속성, 값 인스턴스·시점, 중복 그룹 | 동일 사실 반복과 새로운 사실 구분 |
| 주석 | 평가자별 라벨, 불일치 이유, 합의 결과, 근거 버전 | 사람 정답의 불확실성 보존 |
| 예측 | 모델·체크포인트·양자화·프롬프트 버전, 출력 분포, 보류, 실행 시간 | 재현과 보정 |
| 평가 전용 | 고정 가중치별 점수, 독립 전문가 쌍대 선호 | 정책 선택기에 정답이 들어가지 않도록 별도 저장 |

`fact_ref`가 같다는 이유는 따로 남긴다. 단순 문자열 해시로 사람을 합치지 않는다. 같은 사람의 같은 검사 항목이라도 날짜·값이 다르면 다른 사실일 수 있다. 이 세부 기준을 사람이 먼저 작성해야 집계 알고리즘을 채점할 수 있다.

## 3. 데이터 구성과 주석

### 첫 파일럿

기존 9/22의 96건을 확보·재현할 수 있으면 먼저 사용한다. 확보하지 못하면 새로 **200~300개의 필드-문맥 사례**를 만든다. 이는 필요한 최종 표본 수를 추정하고 주석 지침을 고치는 파일럿이며 논문 성능 확정용이 아니다.

최소 네 종류의 서비스 문맥을 포함한다. 한국어 자유서술과 정형 식별자가 둘 다 있어야 한다. 인가 위반 응답만 모으는 것과 분류용 음성 사례를 빼는 것은 다른 일이다. 위반 응답 안에도 비개인정보 필드가 있으므로 충분히 포함한다.

### 최종 평가의 규모 제안

**서로 다른 서비스 또는 스키마 계열 6~8개, 60~80개 엔드포인트, 의미 있는 필드-문맥 사례 800~1,200개**를 준비하는 안이다. 수량 자체가 통계적 충분성을 보장하지 않는다. 파일럿의 서비스 간 차이·민감 유형 빈도·검토 시간에 따라 검정력과 주석 가능량을 계산해 조정한다.

같은 자체 API의 키만 바꾼 복제본을 독립 서비스 8개로 세면 안 된다. 외부 자료를 확보하지 못하면 ‘통제된 합성 API의 서비스 계열’로 보고하며 실제 기업 일반화는 주장하지 않는다.

### 필수 반례 묶음

- 특정인의 건강상태 / 일반 건강 안내 / 가족의 건강상태 / 가정·부정 표현.
- 사람 이름 / 병원·법인·상품 이름 / 동명이인 / 별명.
- 실제 식별자 / 같은 길이의 주문번호 / 빈 값 / 마스킹 / 예시·테스트 값.
- 같은 이메일 재전송 / 다른 사람의 같은 연락처 / 한 사람의 새 연락처.
- 공개 개인정보 / 비공개 개인정보 / 회사 공용 연락처.
- 한글·영문·한영 혼합, 띄어쓰기·조사·숫자 포맷 변화.
- 의미가 같은 JSON 키 변경·순서 변경·중첩 이동과 의미가 실제 달라지는 경로 변경.
- 잘린 본문·배열 일부만 수집·URL만 있는 이미지·확인 불가능한 주체.

정답에는 확실한 사례, 평가자 불일치 사례, 입력만으로 판단할 수 없는 사례를 표시한다. 애매한 사례를 시험셋에서 지우지 않는다. 확정 가능한 부분의 성능과 불충분 입력에 대한 적절한 보류를 함께 평가한다.

### 분할과 사람 평가

학습·확률 보정·개발·최종 시험을 분리한다. 작은 표본에서는 서비스 계열을 통째로 번갈아 제외하는 평가를 할 수 있으나, 마지막 보고용 서비스 계열은 설계 중 보지 않는 것이 좋다. 합성 생성 템플릿과 거의 같은 대조쌍도 같은 분할에 둔다.

두 평가자는 모델 출력·순위를 보지 않고 독립 주석한다. 분류 일치율과 유형별 불일치를 보고한다. 전문가에게 순위를 물을 때는 모델명·우리 점수·제안 방법을 숨기고 같은 사건 요약을 보여준다. 확정 순서가 어려우면 공동 우선군이나 쌍대 선호로 받는다.

평가자 합의는 절대적인 법적 정답이 아니다. 분류 지침과 해석 근거를 공개하고 해결되지 않은 불일치는 보존한다.

## 4. 비교 실험을 세 층으로 분리

### 실험 A. 분류 오류의 원인

동일 사례에서 다음 네 입력을 비교한다.

| 입력 | 제공 내용 | 확인할 것 |
|---|---|---|
| A | 필드명 | 현재 CIM 중심 입력의 한계 |
| B | A+JSON 경로·메서드·형제 키·정규화 엔드포인트 | 값 없이 얻는 문맥의 이득 |
| C | B+로컬 부분 마스킹 값 | 처리 범위 축소와 의미 손실 |
| D | B+로컬 원문 값 | 자유서술 의미·주체 판단의 추가 이득 |

한국어/영어 대조는 같은 사례를 사람이 검수한 대응쌍으로 구성한다. 언어별 길이, 과도한 설명 추가, 부정·관계 표현 변화를 기록한다. 번역만으로 인과를 확정하지 않는다.

규칙+CIM, 문자 특징 기반 지도학습, 한국어 인코더, 현재 로컬 결정 모델을 비교한다. 시간·GPU 조건이 다르면 비용을 표시한다. 모형 선택은 개발셋에서 끝내고 최종 시험 결과로 프롬프트를 다시 고치지 않는다.

### 실험 B. 집계 오류와 불확실성

분류 정답을 고정한 상태에서 집계 방법을 비교한다. 그래야 중복 제거 이득을 모델 성능 개선과 섞지 않는다.

- B0: 등장 필드 가중합.
- B1: 고유 개인정보 유형만 합산.
- B2: 확인된 주체·속성·값·시점의 고유 사실 집합.
- B3: B2+확인 불충분 사실의 하한·상한, 검토 상태.

동일 응답을 1·5·50회 반복, 배열 순서 변경, 페이지 겹침, 같은 문자열의 다른 사람, 한 사람의 여러 사건을 넣는다. 의미가 같은 반복에는 내용 영향도가 불변이고, 새로운 사람·사실에는 변화해야 한다. 이런 성질의 달성은 기본 정확성으로 보고한다.

가중치는 최소 세 개의 명시된 예시 조건과, 전문가가 허용한 범위를 비교한다. 합성 감사의 `0/1/5/10`, `0/1/5/5`, `0/1/10/5`는 법정 점수가 아니다. 연구 목적에 맞는 범위는 별도로 정해야 한다.

### 실험 C. H2 검토 대상 선택

선택한 분류기와 집계 방식은 모든 정책에 동일하게 적용한다. 교정 전 예측도 동일하다.

| 정책 | 다음에 볼 항목 |
|---|---|
| C0 검토 없음 | 없음 |
| C1 무작위 | 고정 시드의 임의 항목 |
| C2 불확실성 | 보정된 확신도가 낮거나 엔트로피가 높은 항목 |
| C3 잠재 영향 | 가능한 최고 민감도와 노출 규모가 큰 항목 |
| C4 제안 | 예상되는 수정 선택 손실 감소 / 검토 비용이 큰 항목 |
| C5 정답을 아는 상한 | 평가에만 사용하는 이상적 선택. 실제 방법의 경쟁 기준선으로 위장하지 않음 |

검토 예산은 전체 후보의 0·5·10·20%와 실제 소요 시간 두 축으로 보고한다. 한 문장과 긴 메모를 둘 다 한 건으로 세면 비용이 불공정할 수 있다. 후보 수가 아니라 주석된 단위와 실제 읽는 범위를 정의한다.

1차 실험은 선택된 항목만 정답으로 바꿔 주는 **이상적 검토자**로 정책 자체의 가능성을 잰다. 2차는 실제 사람 또는 다른 로컬 모델이 재검토하며 정확도·시간을 측정한다. 1차 결과를 운영 성능으로 쓰지 않는다.

정책은 미선택 항목의 정답을 읽지 못한다. 어떤 항목을 고를지 결정한 다음에만 평가 프로그램이 선택된 항목의 정답을 공개한다. 같은 모델의 자기 검토와 이질적인 검토를 구분한다.

## 5. C4를 구체적으로 구현하는 방법

### 최소 구현

1. 현재 라벨 분포와 집계 규칙으로 엔드포인트 점수와 top-k를 계산한다.
2. 검토 후보 하나의 가능한 라벨을 바꿔 보고 top-k가 달라지는지 계산한다.
3. 바뀔 가능성과 그때의 선택 가치 차이를 예측 분포로 평균 낸다.
4. 예상 검토 시간으로 나눠 우선순위를 정하고 하나를 검토한다.
5. 검토 결과로 점수와 후보 우선순위를 다시 계산한다.

가능한 이론적 표현은 **완전정보의 기대가치**다. `Y`는 모르는 정답 라벨, `A`는 수정할 k개 대상, `U(A,Y)`는 사전에 고정한 선택 효용이다.

```text
V(f) = Σ_y p(Y_f=y) × max_A E[U(A,Y) | Y_f=y]
       − max_A E[U(A,Y)]
priority(f) = V(f) / expected_review_cost(f)
```

이는 사람 검토가 완벽하다는 이상적 조건이다. 실제 재검토가 틀린다면 검토 결과의 오차 분포를 포함한 정보 가치로 바꿔야 한다. 확률이 보정되지 않았거나 항목 간 상관을 무시하면 추정이 어긋난다. **새 이론이라고 주장하지 않는 기준선 구현안**이며, M01 및 정보 가치 관점에 기반한다.

처음부터 복잡한 최적화 신경망을 학습할 필요는 없다. k 경계 근처의 필드만 보는 단순 근사와 비교하고, 후보 계산에 드는 시간까지 포함한다. 하나의 CIM 별칭을 고치면 여러 항목이 바뀌는 경우에는 묶음 후보로 별도 비교한다. 서로 보완적인 두 검토가 필요한 경우 탐욕적 단일 선택이 실패할 수 있으므로 실패 사례도 남긴다.

## 6. 평가 지표의 정확한 의미

### 주지표: 수정 대상 선택 손실

고정한 비음수 점수 `S(e)`와 동일 수정 비용 가정에서, 정답 top-k의 점수 합을 `U*`, 예측으로 선택한 k개의 **정답 점수 합**을 `Uhat`이라 한다.

```text
선택 손실 = (U* − Uhat) / U*       (U*>0)
U*=0인 묶음은 별도로 보고하며 손실은 0으로 둔다.
```

동점인 다른 엔드포인트를 선택해도 같은 효용이면 손실은 0이다. 반면 ID 일치율은 불필요한 오류로 셀 수 있다. 이 지표는 **명시한 점수 모형 아래의 효용 손실**이지 실제 피해 금액이나 법적 피해 비율이 아니다.

| 층 | 함께 보고할 지표 |
|---|---|
| 분류 | 유형별 precision·recall·F1, 비개인정보 FPR, 각 분모, 미탐 유형, 다중 라벨 성능 |
| 주체·집계 | 주체 연결 precision/recall, 중복 합침·분리 오류, 고유 사실 수 오차 |
| 순위 | 선택 손실, 정답 최고점 대상 선택률, 동점 고려 top-k, Kendall tau-b 보조 |
| 검토 | 예산별 손실 곡선, 손실 감소/분, 검토 후 잔여 고위험 미탐 |
| 보류 | 자동 판정 비율, 자동 확정 비교쌍 오류율, 미해결 항목 수, 전체 대비 미탐 |
| 운영 | p50/p95 지연, 처리량, 메모리·VRAM, 검토 계산 시간, 외부 원문 전송·로그 잔존 |

FPR=FP/(FP+TN), FNR=FN/(FN+TP)다. 서로 다른 분모의 ‘오류 5%’를 같은 오류 건수처럼 비교하지 않는다. 다중 클래스의 일반→민감 오분류는 개인정보/비개인정보 이진 FPR에 드러나지 않으므로 혼동행렬도 필요하다.

주석한 **관측 사실 전체**를 분모로 두고 보류·분석 실패·잘린 응답을 별도 상태로 계산한다. 쉬운 성공 사례만 모은 평균을 내지 않는다.

### 신뢰구간과 통계

같은 서비스·엔드포인트의 필드들은 독립 표본이 아니다. 서비스 또는 스키마 계열을 묶어 재표집하고, 정책 간 차이는 같은 자료에서 짝지어 계산한다. 서비스가 6개뿐이면 수천 필드가 있어도 외부 일반화의 근거가 강해지는 것은 아니다. 서비스별 결과와 넓은 구간을 그대로 보고한다.

파일럿으로 효과 크기·분산을 얻은 뒤 최종 표본 규모를 정한다. 다수 모델과 임계치를 시험한 다음 가장 좋은 하나만 보고하지 않는다. 주가설·주지표·예산을 사전에 고정하고 나머지는 탐색으로 표시한다.

## 7. 중간·최종 발표용 정량 목표 예시

다음은 **성공 판정 기준의 제안이며 달성 결과가 아니다.** 파일럿을 보고 시험셋 개봉 전에 확정한다.

| 항목 | 사전 목표 예시 | 해석 주의 |
|---|---|---|
| 주가설 | 10% 검토 예산에서 C2 대비 평균 선택 손실 20% 이상 상대 감소, 짝지은 차이의 95% 구간 보고 | 기준선 손실이 0이면 상대 개선은 정의하지 않고 절대 %p와 동등성 보고 |
| 중요 항목 보존 | 민감·고유식별 재현율 감소 2%p 이내 | 비열등성 주장을 하려면 구간까지 이 경계 안에 있어야 함 |
| 실용성 | 같은 검토 시간에서도 개선 유지 | 건수만 같은 비교로 끝내지 않음 |
| 보류 남용 방지 | 동일 자동 처리 범위에서 오류 비교, risk-coverage 곡선 공개 | 특정 보류율의 최고 수치만 선택하지 않음 |
| 집계 정확성 | 정의상 같은 사실의 반복에 영향도 불변, 새로운 사실은 보존 | 이것은 합성 변환 검사로 확인하는 정확성 요건 |
| 데이터 처리 | 시험 중 응답 원문 외부 전송 0바이트, 비허용 로그 잔존 0건 | 관측한 시험 범위의 결과이며 시스템 전체의 보안 인증 아님 |

중간 발표에는 목표 숫자뿐 아니라 기준선·분모·자료 수·남은 불확실성을 같이 낸다. 최종에는 개선되지 않은 서비스와 실패 유형도 포함한다.
