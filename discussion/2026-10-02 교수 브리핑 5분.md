## 1. 선택한 문제, 40초

### 화면

**테스트 객체의 설정 근거를 이용한 읽기 BOLA 판정**

- 타인 객체를 읽었다는 사실만으로 접근 위반을 확정하기 어렵다.
- 공개·공유 조회는 정상일 수 있다.
- 전체 객체 권한표 대신 테스트 객체 설정을 입력하고, 근거 부족은 보류한다.

### 대본

우리 팀은 읽기 BOLA의 판정 문제 하나를 본체로 정했다.
다른 계정으로 객체를 조회하는 검사 자체는 기존 연구에도 있다.
우리가 확인하려는 것은 그 조회 성공이 정상 공개·공유인지 실제 위반인지 구분하는 데 필요한 근거와 비용이다.
권한 정보를 없애는 것이 아니라, 전체 객체 권한표 대신 직접 만든 테스트 객체의 설정을 쓰는 방법이다.

## 2. 문제를 확인한 예비 결과, 50초

### 화면

| 대상 | 단순 규칙 오탐 | 실제 위반 |
|---|---|---|
| Gitea 공개·비공개·공유 | 8/18 | 0건 |
| Memos 공개·로그인 공개·비공개 | 3/6 | 0건 |

저장된 예비 결과 기준. 제안 방법의 성능은 아직 미측정.
그림: S1, S5. 아직 촬영하지 않았다면 결과 표로 설명한다.

### 대본

공개·비공개·공유 저장소를 만든 Gitea에서 타인 계정의 HTTP 200을 모두 위반으로 보는 규칙은 18건 중 8건을 오탐했다.
공개 메모와 로그인 사용자 공개 메모를 만든 Memos 개별 조회에서도 6건 중 3건을 오탐했다.
두 실험에는 실제 위반이 없어서 재현율을 말할 수 없다.
현재 결과는 단순 규칙의 문제를 확인한 것이고 우리 방법의 성능을 입증한 결과는 아니다.

## 3. 선행연구와 검증할 차이, 60초

### 화면

| 선행연구 | 이미 한 일 | 우리가 비교할 조건 |
|---|---|---|
| BACScan, CCS 2025 | 두 계정이 탐색한 URL·내용이 같으면 공개로 제외 | 허용된 객체가 한쪽 탐색에서 빠지는 조건 |
| AuthProbe, 2026 사전논문 | 목록으로 계정별 객체 수집, 다른 계정 응답의 객체 일치 검사 | 공개·공유 혼합 조건의 권한 근거 |

**검증 질문:** 설정 근거를 추가하면 오탐·미탐·준비 비용이 어떻게 달라지는가?

직접 비교 요약: B에게 허용된 공유 객체가 두 계정 관찰에 모두 있으면 BACScan·AuthProbe도 제외할 수 있다. B 관찰에서만 빠지고 직접 조회는 성공하는 경우 두 절차가 위반 후보를 낼 수 있다. 설정 근거 판정은 이 둘을 같은 허용 접근으로 판단한다.
이는 원문 절차에서 도출한 조건부 분석이며 실행 결과는 아니다. 전체 사례표는 [선행연구 직접 비교 - 객체별 권한 판단](../docs/research/%EC%84%A0%ED%96%89%EC%97%B0%EA%B5%AC%20%EC%A7%81%EC%A0%91%20%EB%B9%84%EA%B5%90%20-%20%EA%B0%9D%EC%B2%B4%EB%B3%84%20%EA%B6%8C%ED%95%9C%20%ED%8C%90%EB%8B%A8.md)의 10/2 보강을 따른다.

### 대본

공개 페이지를 거르는 것은 BACScan이 이미 한다.
다중 계정으로 요청하고 반환 객체를 확인하는 것도 AuthProbe가 한다.
그래서 공개를 고려한다거나 객체 ID를 확인한다는 점만으로 차별성을 주장하지 않는다.
우리는 정상 공개·공유 객체가 한쪽 계정의 탐색이나 목록에 나타나지 않는 조건을 만든다.
이때 관찰 기반 판정과 객체 생성 때 기록한 설정 근거 기반 판정을 비교한다.
추가 입력을 쓰는 만큼 그 준비 시간도 측정해야 한다.
현재는 차별성 후보이며 기존 방식보다 낫다는 결론은 아직 없다.

근거: [BACScan §4·§6](https://seclab.cse.cuhk.edu.hk/papers/ccs25-BACScan.pdf), [AuthProbe §III·§V](https://arxiv.org/html/2607.20574).

## 4. 방법과 판정 범위, 50초

### 화면

객체 생성·공유 설정 기록 → 계정별 조회 → 반환 객체 확인 → 근거와 대조

| 조건 | 결과 |
|---|---|
| 읽기 금지 근거 + 해당 객체 반환 | 위반 확정 |
| 읽기 허용 근거 + 해당 객체 반환 | 허용된 접근 |
| 정책 근거 또는 객체 일치 확인 부족 | 보류 |

한 객체의 결과를 다른 객체로 자동 확대하지 않는다.

### 대본

소유자, 비공유 계정, 공유 계정과 비로그인 계정을 분리한다.
객체를 만들 때 공개 범위와 공유 대상을 기록한다.
금지된 계정의 응답에 그 객체가 실제 반환되면 위반으로 확정한다.
공개·공유 설정상 허용된 계정이라면 정상 접근으로 분리한다.
설정을 모르거나 응답이 어떤 객체인지 확인할 수 없으면 보류한다.
테스트 객체가 아닌 운영 객체 전체의 권한을 추정하는 것은 이번 범위 밖이다.

## 5. 실험과 성공 기준, 50초

### 화면

- Gitea: 정상 공개·공유 오탐 평가.
- Memos: 실제 읽기 취약 경로와 접근 거부 대조군 확보.
- 비교: 단순 규칙, 객체 일치 기준선, BACScan식 필터, 설정 근거 판정.
- 지표: 재현율, 오탐률, 보류율, 준비 시간·객체 수·추가 요청 수.

보류한 실제 위반은 미탐으로 센다.
Memos 0.9.1의 수정 여부는 경로별 확인이 필요하다.

### 대본

Gitea는 공개·공유 조건의 정상 사례를 만드는 데 사용한다.
Memos는 실제 읽기 위반과 대응 대조군을 확보할 후보다.
소스에서 목록 조회의 공개 범위 질의 인자 처리를 확인했지만 아직 누출을 재현하지 않았다.
0.9.1을 수정 버전으로 단정하지 않고 같은 요청이 차단되는 버전을 먼저 확인하겠다.
같은 요청 집합으로 판정기를 비교하고 실제 위반을 보류하면 재현율에서 미탐으로 센다.
오탐만 줄이고 실제 위반을 놓치거나 준비 비용이 줄지 않으면 가설이 지지되지 않은 것으로 보고한다.
