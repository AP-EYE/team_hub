# 4인 프로젝트 착수 계획

## 프로젝트 정의

**정책 기반 API 인가 진단과 로그 기반 개인정보 노출 분석을 결합한 내부망 보안 도구**를 만든다. 한국어 로컬 AI는 필드 의미와 비정형 내용의 분류를 보조한다. 원문 사고를 모두 재구성하는 포렌식 시스템이나 법률적 결합 식별 가능성을 자동 확정하는 도구로 정의하지 않는다.

## 이번 데모로 확인하는 질문

1. 다른 계정으로 실제 로컬 API를 호출하고 정책과 결과를 비교할 수 있는가?
2. 공개 프로필·공유·관리자 허용 조건을 공격과 구별하는가?
3. 요청자와 응답의 정보주체를 분리해 DB에 기록하는가?
4. 여러 API의 같은 의미 필드를 정규화하고, 같은 요청자가 받은 자료를 연결할 수 있는가?
5. AI 분류와 CIM 후보가 규칙 대비 유용한가? 실행 가능성과 정확도는 구분한다.
6. 작은 시스템에서 실패를 관측·수정·재검증하고 근거를 남길 수 있는가?

실제 수치와 결론은 demo-results.md와 원자료를 따른다. 이 문서의 제안 일정이나 통과 기준을 이미 달성한 결과로 읽으면 안 된다.

## 제안 일정: 8주, 주당 가용 시간은 팀에서 확정

| 기간 | 산출물 | 완료 조건 |
|---|---|---|
| 1주 | 한 도메인의 데이터/권한 계약, 평가셋 1차 | 공개·공유·테넌트·역할·정보주체 정의를 담당자끼리 교차 검토 |
| 2주 | 로컬 모델 2~3개 비교와 규칙 기준 | 정밀도·재현율·검토율·지연을 같은 독립 평가셋에서 측정; 미달 기능은 후보 전용으로 유지 |
| 3~4주 | mitmproxy addon 또는 기존 gateway 통합, 인가 작업자 | 운영 트래픽 관찰과 격리된 능동 진단을 분리; 상태 변경 없는 허용 대상에서 재현 |
| 5주 | 로그 DB·정규화 레지스트리·검토 화면 | 매핑 버전/근거/승인 이력, 테넌트 오결합 방지 |
| 6주 | 개인정보 분류·노출 항목 결합·조사 보고서 | 관측/잠재/미확인 범위 표시, 중복 정보주체 집계 기준 검증 |
| 7주 | 독립 서비스 반례·장애·부하 평가 | 실패한 사례와 누락 로그, 모델 오류를 숨기지 않고 보고 |
| 8주 | 재현 가능한 배포·교수 브리핑·포트폴리오 | 다른 팀원 PC에서 새로 설치하여 같은 핵심 결과 재현 |

## 역할과 인터페이스

| 담당 | 책임 | 다른 담당에게 제공할 계약 |
|---|---|---|
| A: 인가·공격 시나리오 | 소유/공유/역할/테넌트 정책, BOLA/BFLA/BOPLA 검증 | 케이스 입력, 기대 판정, 증거 조건 |
| B: 수집·DB·정규화 | 프록시, 비밀 제거, 로그 내구성, SQL 결합 | 이벤트·정보주체·필드 관측 스키마, 매핑 버전 |
| C: AI·개인정보 평가 | 한국어 데이터셋, 규칙/모델/혼합 비교, 후보 분류 | 라벨·근거·불확실성·모델 버전·실측 지연 |
| D: UI·통합·품질 | 대시보드, 증거 탐색, 재실행, CI·배포 | API 계약, 설치법, 실패/회귀 테스트와 보고서 |

역할별 단독 구현으로 끝내지 않고 정책은 다른 담당이 반례를 작성하고 모델 정답은 두 명이 검토한다. 이 과정 자체가 취업 포트폴리오의 설명 근거가 된다.

## 초기 범위에서 제외

- 임의 회사 API를 무설정으로 이해해 인가 정답을 자동 생성하기
- 모든 개인정보/이미지/영상의 법률적 분류와 재식별 가능성을 자동 확정하기
- 사고가 난 뒤 과거에 수집하지 않은 자료를 복원하기
- 실제 서비스에 변경/삭제/결제 요청을 자동 재전송하기
- LLM 결과만으로 즉시 차단하거나 규칙을 자동 승인하기

## 실험 설계 개선

이번 작성자 합성 24건/8건은 실행 확인용이다. 착수 후 별도의 팀원이 처음부터 보지 않은 필드명·문장·API 구조를 준비해 개발셋과 평가셋을 분리한다. 모델을 바꿀 때 같은 평가셋을 수차례 보며 프롬프트를 고치면 독립 평가라고 주장하지 않는다. 규칙 대비 전체 정확도뿐 아니라 민감정보 누락, 일반 안내 오탐, 모호한 스키마의 보류율을 함께 비교한다.

사례 수 목표는 초기 최소 100건 정도에서 시작하되 클래스 균형과 다양한 구조를 우선한다. 이 숫자는 정확도 보증을 위한 통계적 표본 크기 계산 결과가 아니다.

## 교수님께 보여줄 핵심

- 요청·응답 기록을 실제 PostgreSQL에서 조회하고, 이벤트 ID로 판정의 근거를 추적한다.
- 다른 계정의 응답이 보여도 공개·공유·관리자 조건에서는 경보하지 않는다.
- 별칭 정규화와 데이터 연결을 실제로 수행하되 AI 후보·확정 규칙·법적 판단을 구분한다.
- 로컬 AI의 실패 결과와 대안을 같은 데이터로 비교한다. 실패한 기술도 선정 근거로 남긴다.
- 취약한 버전과 수정한 버전에 같은 시나리오를 실행해 회귀 결과를 비교한다.
