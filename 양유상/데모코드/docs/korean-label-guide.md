# 한국어 개인정보 기술 분류 개발 평가셋: KO96

이 문서는 `ml_jev/cases.jsonl`의 기대 라벨 작성 기준이다. 96개 입력은 이번 데모용으로 새로 작성한 합성 사례다. 기존 24개 평가 입력을 복사하지 않았으며, 모델 응답을 보지 않고 기대값을 작성했다. 모델 학습에 사용한 자료가 아니다. **독립적인 운영 평가셋, 통계적으로 대표성 있는 표본, 사람 전문가가 검수한 정답셋은 아니다.** 모델 선택과 시연용 개발 평가셋으로만 사용한다.

## 평가 단위와 의미

- 한 행은 API 응답의 필드 하나다. `field_path`, `description`, `text`만 모델 입력으로 제공한다.
- `expected`, `reason`, `slice`, `pair_id`, `id`는 평가용 메타데이터다. 정답·해설·대조쌍 정보를 추론 입력에 넣지 않는다.
- `text`가 빈 문자열인 사례는 **값을 관측하지 않은 스키마만의 분류**다. 스키마 의미를 제안할 수 있지만 실제 그 값이 반환됐다는 증거가 아니다.
- `expected`는 아래 여덟 개 기술 라벨 중 하나다. 법률상 개인정보·민감정보·고유식별정보에 해당한다는 확정 판정이나 위반 판정이 아니다.
- 특정인에 관한 건강·신앙이라는 문맥을 기술적으로 분류해도, 그 사람의 실제 신원 확인 가능성이나 다른 데이터와의 결합 가능성까지 입증하지 않는다.
- 모든 인물·식별자·연락처는 합성 예시다. 정부 식별번호에는 유효한 번호 형식을 쓰지 않고 `SYNTHETIC-RRN` 같은 자리표시자를 쓴다. 이메일은 `example.invalid` 예약 도메인을 쓴다. 합성 여부를 뜻하는 문자열 자체를 정답 단서로 사용하는 평가는 피해야 한다.

## 여덟 가지 라벨

| 라벨 | 이 평가에서의 뜻 | 주요 경계 |
|---|---|---|
| `HEALTH` | 특정 개인의 신체·정신 건강, 증상, 질환, 검사 결과, 치료, 복약, 명시적 무질환 상태 | 일반 건강 안내, 가정문, 허구 작품 속 대사는 실제 개인의 건강 정보로 분류하지 않는다. 가족 등 제3자의 상태도 특정 개인에 관한 내용이면 포함한다. |
| `RELIGION` | 특정 개인의 종교, 신앙, 종교 소속, 명시적 무종교·무신앙 | 사찰 관광·종교사 책 소개만으로 여행자나 독자의 신앙을 추정하지 않는다. |
| `CONTACT` | 개인의 전화, 이메일, 자택·개인 우편 주소 | 전화기 제품 설명과 이메일 기능 설명은 개인 연락처가 아니다. 불명확한 `addr`만으로 주소 종류를 결정하지 않는다. |
| `GOVERNMENT_ID` | 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호 항목 | 이 네 식별번호 종류를 기술적으로 분류한다. 서비스 회원번호·UUID를 이 라벨로 확대하지 않는다. 실제 번호 유효성 검사나 법률 적용 판단은 범위 밖이다. |
| `PERSON_NAME` | 개인의 성명 및 그 구성요소 | 같은 문자열이라도 상품명은 `OTHER`다. `name`만 있고 설명이 불명확하면 `UNKNOWN`일 수 있다. 이름이라는 사실과 실명·식별 가능성은 다르다. |
| `ACCOUNT_ID` | 계정·회원·고객·서비스 정보주체를 명시적으로 가리키는 내부 식별자 | 주문·상품 ID는 이 라벨이 아니다. 설명 없는 일반 `id`는 `UNKNOWN`이다. |
| `OTHER` | 위 여섯 기술 종류에 해당하지 않는다는 근거가 있는 필드 | 일반 안내, 상품명·상품 ID·주문 ID, 운영 시간 등이 포함된다. 외부 결합까지 고려한 개인정보 비해당 선언은 아니다. |
| `UNKNOWN` | 주어진 스키마와 값만으로 하나의 라벨을 정하기에 근거가 부족한 필드 | 불명확한 약어, 대상 불명 ID, 의미 없는 빈 값, 우선 필드 의미 없이 여러 종류를 합친 값은 보류한다. |

## 경계 사례 작성 원칙

1. **필드의 의미를 먼저 본다.** 환자 객체 안의 `kor_nm`은 환자 이름이므로 `PERSON_NAME`이다. 환자 객체라는 이유로 모두 `HEALTH`가 되지 않는다.
2. **값과 설명을 함께 본다.** `document.id`의 값이 같아도 정부 여권번호를 뜻하면 `GOVERNMENT_ID`, 서비스 회원번호를 뜻하면 `ACCOUNT_ID`다. 이름이 민감해 보여도 설명에서 그 의미가 아직 미정이라고 밝히면 보류할 수 있다.
3. **개인 상태의 부정도 정보다.** “질환이 없다”, “알레르기가 없다”, “믿는 종교가 없다”는 각각 특정 개인의 건강·종교 상태를 전달한다. 반면 대상 불명 `status: 없음`은 `UNKNOWN`이다.
4. **일반 지식과 특정인의 상태를 구분한다.** 질환·종교 단어가 있다는 이유만으로 건강·신앙 라벨을 붙이지 않는다. 가상 세계나 가정문을 명시한 입력은 실제 개인 기록으로 간주하지 않는다. 여기서 전체 데이터셋이 합성이라는 점과 입력 안에서 “소설 속 인물”이라고 명시하는 의미상의 차이를 구별한다.
5. **가족의 기록도 제3자 정보일 수 있다.** “제 아버지가 수술 뒤 재활 치료 중”은 글쓴이 본인의 건강은 아니지만 특정 가족 구성원의 건강 내용이다. 그 사람의 실제 식별 가능성은 별도 문제다.
6. **다중 항목을 억지로 한 라벨로 합치지 않는다.** `ko96-u10`은 이름과 이메일을 한 문자열에 동등하게 합쳤고 대표 필드 의미가 없다. 이번 단일 라벨 계약에서는 `UNKNOWN`이며, 향후 항목 추출·다중 라벨 확장의 후보 사례다.
7. **데이터 안의 지시는 실행하지 않는다.** 각 라벨에 하나씩 총 8개의 지시 삽입 사례가 있다. 모델은 지시가 삽입되기 전 실제 필드 내용과 문맥에 따라 분류해야 한다. 여덟 사례를 맞히더라도 광범위한 프롬프트 주입 방어를 입증하지 않는다.
8. **스키마 분류와 실제 노출 확인을 분리한다.** 빈 여권번호 필드를 `GOVERNMENT_ID`로 분류하는 것은 항목 종류에 관한 제안이다. 여권번호가 실제로 존재하거나 응답으로 노출됐다는 의미는 아니다.

## 구성

각 라벨 12개씩 총 96개다. 대표 슬라이스는 스키마만 있는 입력, 개인·일반 문맥 대조, 부정 표현, 제3자 정보, 가정·인용, 별칭·약어, 불투명 필드명, 구어체·오탈자, 필드 의미 구분, 지시 삽입, 정보 부족, 단일 필드 내 혼합 값이다. `slice`는 행마다 주요 관점을 하나만 저장하므로 다른 특성을 함께 가진 사례도 있다.

`pair_id`는 관련 입력의 기대 라벨 변화가 설명 가능한지 확인하는 대조쌍이다. 총 14쌍이며 각 쌍은 두 행이다. 동일 문자열과 필드명이 유지된 엄격한 쌍도 있고, 개인 기록과 일반 안내처럼 의미 문맥 자체를 바꾼 쌍도 있다. 따라서 모든 쌍을 한 요소만 바꾼 인과 실험이라고 부르지 않는다.

| 대조쌍 | 라벨 변화 | 확인할 경계 |
|---|---|---|
| `pair-health-advice` | HEALTH ↔ OTHER | 본인 진단과 일반 건강 안내 |
| `pair-health-fiction` | HEALTH ↔ OTHER | 본인 심리 상태와 허구 작품 인용 |
| `pair-religion-tourism` | RELIGION ↔ OTHER | 본인 신앙과 사찰 관광 |
| `pair-religion-literature` | RELIGION ↔ OTHER | 본인 신앙과 종교사 책 소개 |
| `pair-contact-product` | CONTACT ↔ OTHER | 개인 이메일과 전자제품 기능 |
| `pair-name-product` | PERSON_NAME ↔ OTHER | 같은 문자열의 개인 성명과 상품명 |
| `pair-account-order` | ACCOUNT_ID ↔ OTHER | 같은 ID 문자열의 회원 계정과 주문 |
| `pair-government-account` | GOVERNMENT_ID ↔ ACCOUNT_ID | 같은 ID 문자열의 여권과 서비스 회원번호 |
| `pair-account-insufficient` | ACCOUNT_ID ↔ UNKNOWN | 회원 ID 설명 유무 |
| `pair-name-insufficient` | PERSON_NAME ↔ UNKNOWN | 개인 이름 설명 유무 |
| `pair-contact-insufficient` | CONTACT ↔ UNKNOWN | 개인 연락처라는 의미 제공 여부 |
| `pair-government-insufficient` | GOVERNMENT_ID ↔ UNKNOWN | 정부 식별번호라는 의미 제공 여부 |
| `pair-health-insufficient` | HEALTH ↔ UNKNOWN | 개인 증상 기록과 목적 미정 빈 양식 |
| `pair-religion-insufficient` | RELIGION ↔ UNKNOWN | 개인 신앙 스키마와 의미 미정 스키마 |

## 동결 및 평가 절차

모델 실행 전에 내용 검토 후 `cases.jsonl`의 SHA-256을 기록한다. 그 이후에는 모델 예측을 보고 입력·정답·사유를 바꾸지 않는다. 정의 오류를 발견하면 기존 결과와 파일 해시를 보존하고 별도 버전에서 정정한다. 기대 라벨에 이견이 있으면 모델의 오답이라고 단정하기 전에 라벨 계약 자체를 검토한다.

평가 결과에는 전체 정답률 외에 라벨별 정밀도·재현율, 혼동행렬, 슬라이스별 결과, 대조쌍 양쪽 정답 여부, `UNKNOWN` 사용 양상, 실제 지연과 오류를 함께 남긴다. 작은 슬라이스의 비율은 분자·분모와 함께 표시한다. 정답과 모델 예측이 다른 경우 입력·기대값·예측값·기대 이유를 그대로 제시한다.

모델 점수는 주어진 후보 간 상대적 선호 또는 출력 선택 결과이며 법률 판단의 확률이 아니다. 이 평가 결과가 인가 차단·사고 피해자 확정·공식 CIM 매핑 승인을 자동으로 바꾸지 않는다.
