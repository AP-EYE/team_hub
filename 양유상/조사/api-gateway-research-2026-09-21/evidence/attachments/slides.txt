## PAGE 5
만드는 것
1단계  엔드포인트 복원
mitmproxy로 실제 앱 트래픽을 받아 경로 변수를 일반화합니다. OpenAPI 스펙이
없어도 동작하는데, 실사고가 난 서비스들은 어차피 스펙을 공개하지 않습니다.
2단계  인가 취약점 탐지
계정 A의 리소스를 계정 B 토큰으로 요청합니다. 응답에 실린 신원이 토큰 주인과 다르
면 위반입니다. 그걸로 판정이 끝납니다.
신원이 안 실리는 엔드포인트에서만 두 응답을 비교합니다.
3단계  노출 영향도 산정 (본체)
새는 필드를 민감정보, 고유식별정보, 일반 개인정보로 나눠 가중합니다. 강남언니 유출
항목이 최고 등급으로 자동 분류되는지가
첫 검증 기준입니다. 순차 ID가 응답에 섞여 있으면 대량 수집 위험으로 가산합니다.
4단계  두 가지 출력
평시에는 수정 우선순위 리포트를 냅니다. 사고가 나면 같은 엔진이 유출 범위 산정서를
냅니다.

## PAGE 7
연구를 넘어서
규제가 수요를 만듭니다
개인정보보호법은 유출을 인지한 뒤 72시간 안에 유출 항목과 규모를 신고하도록 요구합니다.
이 산정을 자동화한 도구가 없습니다. 3단계 출력이 그대로 신고서 초안이 됩니다.
예산 라인이 비어 있습니다
API 보안 제품은 보안팀 예산입니다. 유출 범위 산정은 개인정보보호책임자 예산이고, 그 자리
에는 경쟁 제품이 없습니다.
같이 하면 남는 것
역량 프록시로 API 트래픽을 다루고, 인가 로직을 직접 깨보고, 유출 항목을 법 분류로
옮기는 일까지 한 프로젝트 안에서 겪습니다. 벤치마크로 수치를 내본 경험이 함께
남습니다.
도메인 API 보안, 개인정보보호 컴플라이언스, 침해사고 대응이 맞물립니다. 어느 하나만
아는 지원자와 구별되는 지점입니다.
직무 모의해킹과 취약점 진단, 개인정보보호 컨설팅, 보안 솔루션 개발. 국내 채용에 실
제로 열려 있는 직무들입니다.
웹과 API 취약점 진단은 국내 보안 채용에서 기본 소양으로 요구됩니다. 커널이나 저수준 지식
없이 들어갈 수 있어 진입 비용은 낮은 편입니다.
