## 피드백

### 최한림 교수: 작업 방식

- 모두가 같은 스킬과 같은 컨텍스트로 작업해야 한다. 그러려면 GitHub 레포 세팅이 가장 중요하다. (00:07)
- 노션 자료는 휘발성이다. 지금은 팀원마다 노션 자료를 각자 컴퓨터(Obsidian 등)에 따로 먹이고 있다. GitHub로 통일한다. (00:32~01:14)
- 작업 시작 시 GitHub 싱크만 받으면 팀원의 PR과 자료가 로컬에 오고, Claude나 Codex가 최신 상태에서 작업할 수 있다. 노션 PDF는 AI가 제대로 읽는지 확정할 수 없다. (14:46~15:26)
- Orca 같은 ADE(에이전트 개발 환경)에 GitHub을 연동하고, 작업 전 싱크 자동화와 모바일 페어링을 건다. (16:59~17:35)
- md 작성이 어렵다는 질문에: md 변환 스킬은 많다. 팀 스킬 레포를 만들어 모든 팀원의 AI가 같은 스킬을 자동 인식하게 한다. 수동으로 쓴 문서도 그냥 올리면 된다. GitHub Actions에 쓸 만한 것이 많다. (18:24~20:01)
- 노션은 남이 보기 어렵고(어디에 무엇이 있는지, 언제 올라왔는지 모름), 버전 관리가 잘 안 보이고, 문서가 오염돼도 파악하기 어렵다. GitHub는 리뷰어·승인자가 개입할 수 있다. (20:25~21:40)
- 포트폴리오도 링크 하나로 되고, 교수도 레포를 받아 AI로 프로젝트 구조를 파악할 수 있다. (20:10~20:25)

### 최한림 교수: 연구 방향

- AuthzTrace는 외부자 관점 API 취약점 스캐너다. 팀이 말한 내부 API 게이트웨이 모니터링과 관점이 다르다. 외부 관점이면 다시 구현해야 하는 것 아닌가. (28:15, 33:54~35:19)
- 공개된 API 보안 게이트웨이 오픈소스가 없으면 구현 자체로 의미가 있다. 이미 akto가 있다. (35:29~36:12)
- akto 엔진이 이미 잘 만들어져 있는데 부족한 점 때문에 처음부터 새로 만드는 것은 의미가 약하다. 기여하면 머지와 기여자 인정을 받을 수 있다. 인정되지 않아도 fork해서 한국 특화로 만들 수 있고, fork 버전이 더 인기를 얻기도 한다. (38:16~39:19)
- akto가 AI 네이티브가 아니면 그런 기능을 추가해도 좋다. (40:03)
- 기업이 오픈소스를 도입할 때는 관리 상태와 커뮤니티 규모가 중요하다. 새로 만든 도구는 기능이 좋아도 잘 쓰이지 않는다. (40:57~41:40)
- 한국 관련 내용과 BOLA 관련 내용을 채우면 포트폴리오에 더 좋을 수 있다. (43:57~44:09)

### 조재현 교수: 평가 기준

- 정탐/오탐을 판단할 기준 데이터셋이 먼저 필요하다. 직접 만든 합성 API로 정확도를 재면 "그들만의 리그"가 된다. 연구 결과를 아는 사람이 만든 테스트 데이터는 정확도를 편향시킨다. (22:47~24:30)
- 연구 자체는 의미가 있어 보이나 정확도의 기준을 모르겠다. 기준 데이터셋이 제시되지 않았다. (24:30)
- 리뷰어가 납득할 만한 기준점을 고르는 것이 연구적으로 의미가 있다. (25:37)

- Q. 다른 프로젝트(퍼저 등)가 쓴 데이터셋을 써도 되나?
  A. 된다. 그 논문이 인용한 정확도보다 개선됐음을 보이면 된다. (24:49~25:37, 조재현)
- Q. 네임드가 아닌 학회나 아직 평가받지 않은 논문(arXiv)도 선행연구로 봐야 하나?
  A. 볼 수 있다. 학회 때문에 평가절하하지 말고, 읽어 보고 근거가 부족하면 그것을 보강하는 방향으로 가도 된다. 검증되지 않았으면 직접 검증한다. 개인이 AI로 만든 도구일 수도 있으니 자세히 들여다봐야 선행연구인지 알 수 있다. (25:53~27:44, 조재현)
- Q. 오픈소스 기여는 많이 쓰이는 오픈소스여야 의미가 있나?
  A. akto는 인기가 많고 많이 쓰이는 것 같다. 관리 상태와 커뮤니티가 중요하다. (40:34~41:40, 최한림)
- Q. 머지가 안 돼도 의미가 있나?
  A. fork해서 한국 특화로 만들면 된다. (43:26~43:31, 최한림)

## 팀 발표 요지 (01:47~13:32)

- 공개 API 처리 방식: BACScan과 AuthScope(STT "어시스코프")는 내용·주소가 같으면 공유로 보고 제외한다. "어스프"(정식 이름 TBD)는 로그아웃 상태에서 보이면 공개로 판정한다. AuthProbe(arXiv 2607.20574)는 계정별 열람 가능 목록을 정답으로 쓴다.
- AuthzTrace 재현: 취약 서버에서는 정탐. 고친 서버에서는 비공개 메모 표식 없이 200 OK만 보고 BOLA로 판정하는 오탐.
- 목표: 200 OK만으로 판정하지 않는다. 비공개 내용이 유출된 경우만 BOLA, 볼 수 있는 객체만 나오면 정상, 판단 불가는 보류. 오탐률·재현율로 수치 목표를 세운다(수치는 임의, 변경 예정).
